# 1.5 修复记录与验证边界

本轮针对 1.4.0-codex.2 的使用反馈逐项修缮。反馈中的“实际复现”“机制实验”和“读代码推断”分别核对，没有把所有推断直接当成事实。保留单一原生面板、Claude 与 Codex、订阅登录和手动启用。

| 反馈 | 处理与回归依据 |
| --- | --- |
| 1 工具结果形状错误 | 注册工具统一返回 JSON 文本；原生 Agent、Read 等拒绝使用 deny。测试先检查原始 wire，再解析 JSON，并故意注入旧错误对象及错误内容块，确认检查失败。 |
| 2 manual 过早关闭 | 删除普通主回合结束时的自动 finish；激活→计划答复→批准→派工可跨回合。只在 finished:true、显式 finish 或用户结束时关闭。 |
| 3 缺上下文/依赖 | 写 scope、只读 context、显式依赖副本和新验证产物分开；适用项目指令自动复制。实际 Python 子进程在副本读取依赖并运行测试，标准 TemporaryDirectory 落在显式授权的输出目录，改只读输入会阻止交付。 |
| 4 Windows 状态冲突 | 共享删除读取、唯一临时文件、有界重试及 Windows 原子替换；真实长持句柄、多线程及跨进程回归。暂时的进度持久化失败不杀 worker。 |
| 5 同项目不能并行 | 独立任务锁代替整个源工作区的生命周期锁；使用屏障实测同项目两个独立快照并行。最终写回仍归负责人。 |
| 6 继承危险权限 | 显式固定工作区写、清除额外 roots/直接网络并核验实际 config/read。真实 CLI 在临时危险配置下验证覆盖；不兼容命名权限配置阻止执行，不修改全局配置。 |
| 7 固定 worktree | Claude 模板不再强制；专用只读 review 无 Git/HEAD 要求。只有明确请求 worktree 才检查 Git、HEAD 与脏文件，不默默漏掉未提交输入。 |
| 8 缺 Hook CI/契约 | CI 安装固定官方 2.1.317，实际运行 plugin test；缺工具或失败会使作业失败。两版宿主运行同一套严格契约测试；提供 /savvy-check 验真实会话工具链。 |
| 9 路径规则不同 | 单一 JSON 规则生成宿主可加载 TS，CI 校验生成一致；Python/TS 使用同一案例，普通 tokens.ts、secret.md、credentials.py 不误杀。排除与限制可见。 |
| 10 任务匹配 | 使用 plan_task_id/id/job_id 与短 title 关联，完整 goal 单独保留。 |
| 11 后台计数 | 依据实际 agent.spawn/turn.complete 与运行记录计数，不用 Agent 请求返回即减一。 |
| 12 工具上下文开销 | 除 step 外改为按需发现；关闭模式仍提供必要诊断和查看能力，不以没出现在初始列表就判工具不存在。 |
| 13 安装与备份 | 保留旧包的目录交换、包与配置事务回滚；提交后清理失败为 warning。成功备份默认保留最近 5 份，未知/失败备份受保护。 |
| 14 预览误判 | 保留合法 U+FFFD；不再冒充能从解码后的字符串识别所有坏字节。无安全 realpath 能力时仍拒绝链接，明确说明 macOS 系统别名限制。 |
| 15 上下文比例 | 没有可靠容量时显示未知；不再把任意模型当成 1M。 |
| 16 重复预检 | 成功的 CLI 静态能力短时缓存；配置/CLI/本地认证指纹和 TTL 控制失效。实际权限每次重新校验，keyring 登录不使用无法失效的认证缓存。 |

独立复核还修复：上下文路径别名绕过重叠检查、缺快照时预览回退主目录、只读/排除清单过大造成状态读取失败，以及安装完成后清理失败被误报成安装失败。完整只读哈希验证保留在控制器，状态仅采样并注明总数/截断。

## 哪些验证能证明什么

- Hook 测试在官方 CLI 的原生 Mod 测试环境运行；其 mock 不校验生产工具结果，所以另加严格的原始返回契约观察器。测试能证明这些分支符合预期协议，不能代替完整桌面对话或模型理解测试。
- Python 回归使用真实临时文件、Git 补丁、线程/进程及测试命令，模型事件用可控 fixture，不消耗推理额度。可选 CLI 集成验证 config/read 与参数解析，不发送模型 turn。
- GitHub 同时运行 Python 平台矩阵和原生 Hook 测试。CI 不保存账号/私有项目/运行记录；原生测试通过不等于 macOS / Linux 桌面均已实测。
- `context_paths` 的不可变性与代码交付范围由控制器验证，不是操作系统逐文件 ACL。运行沙箱是工作区级；外部访问仍受宿主和审批机制约束。
- 只读检查不暗中获得文件写权限。需要临时文件/构建产物的测试必须在显式授权的验证位置执行；缺依赖或链接依赖不能通过返回“成功”掩盖。
- 完整生产复验入口是新 Code 会话中的 `/savvy-check`，随后按用户自己的订阅及项目权限使用 `/savvy-start <任务>`。本轮不通过启动另一个 Claude CLI 推理会话来消耗未知外部服务额度。
